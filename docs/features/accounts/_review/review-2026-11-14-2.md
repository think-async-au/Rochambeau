### R1 — [stage-1] F7's success-path refusal and zero-rows failure branch are untested — **Fix now**
- Where: `src/Rochambeau.Api/Modules/Identity/Application/LogIn/LogIn.cs:80-83,115-118`, `tests/Rochambeau.IntegrationTests/Identity/LogInTests.cs:176-202`. AC: AC-06 (T22 DoD).
- Problem: the parallel test sends only wrong passwords, and its status counts usually match the pre-fix code too. A correct guess that is in flight while the account is locked could sign in again and no test would fail.
- Resolution: follow-up TDD task. Add a deterministic integration test with an `IPasswordHasher<Account>` decorator that writes `lockout_end = now + 15 min` through a separate DbContext before delegating. A correct password must get 423 with the stored `lockoutEnd`, no `Set-Cookie`, and an unchanged `access_failed_count`. Repeat with a wrong password to cover the zero-rows branch.

### R2 — [stage-1] A hub connection's 7-day deadline ignores the Player's HTTP activity — **Accepted deviation (Fix now: ADR + reconnect rule)**
- Where: `src/Rochambeau.Api/Modules/Identity/Infrastructure/SessionRevalidationHubFilter.cs:34,42-45,65`. AC: AC-08.
- Problem: the deadline is set when the connection opens and moves only on hub invocations. A connection that only receives pushes is refused after 7 days, even while the Player stays active over HTTP.
- Resolution: owner accepts the per-connection deadline. Follow-up task: amend accounts ADR-0004 Consequences to record the deviation, and require `withAutomaticReconnect` in every `web/src/shared/realtime` hook, so that a refused call reconnects with the still-valid cookie and so renews the deadline. No new server state.

### R3 — [stage-1] AC-08 "opening a real-time connection counts as activity" has no test — **Fix now**
- Where: `tests/Rochambeau.IntegrationTests/Identity/HubSessionRevalidationTests.cs:75,135`, `tests/Rochambeau.IntegrationTests/Infrastructure/TestHubHost.cs:55-58`. AC: AC-08 (test-plan.md:63, accounts ADR-0004:40).
- Resolution: follow-up TDD task with a fake clock. Register at t0. At +6 days, POST `…/negotiate` with the cookie and assert a renewed `Set-Cookie`. At a further +6 days, `GET /api/v1/me` with the renewed cookie must return 200.

### R4 — [stage-1] Some error responses fall outside openapi.yaml — **Fix now**
- Where: `src/Rochambeau.Api/Modules/Identity/Domain/IdentityErrors.cs:11-12`, `src/Rochambeau.Api/Modules/Identity/Infrastructure/SessionCookie.cs:33-34`, `src/Rochambeau.Api/Common/Http/ProblemDetailsDefaults.cs:19-20`. AC: n/a (`contracts/openapi.yaml:390-404` errorCode enum, required).
- Problem: `identity.forbidden` (403) is emitted but missing from the errorCode enum. A non-JSON `Content-Type` on POST `/api/v1/accounts` or `/api/v1/session` returns an undocumented 415 with no `errorCode`.
- Resolution: follow-up TDD task. Add `identity.forbidden` to the enum, with a 403 response component. Map 415 to `400 common.invalid_request`, or give it an `errorCode` and document it. Add a wrong-content-type case to `tests/Rochambeau.IntegrationTests/Host/BadRequestBodyTests.cs`.

### R5 — [stage-2] `ICurrentAccount` is unresolved in a hub's `OnDisconnectedAsync` — **Fix now**
- Where: `src/Rochambeau.Api/Modules/Identity/Infrastructure/SessionRevalidationHubFilter.cs:27-70`. AC: AC-08 (accounts ADR-0004 "for every area").
- Problem: `IHubFilter.OnDisconnectedAsync` keeps its default, so `HubCallerPrincipal.User` is null there and `CurrentAccount` falls back to the untrustworthy `IHttpContextAccessor`. Play will need "who left" in that hook.
- Resolution: follow-up TDD task. Implement `OnDisconnectedAsync` so that it sets the holder from `context.Context.User` before `next`. Add a test hub whose `OnDisconnectedAsync` records `ICurrentAccount.Current`, and assert the recorded value.
