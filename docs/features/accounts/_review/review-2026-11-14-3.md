### R6 — [stage-1] No integration test checks the Administrator role that `ICurrentAccount` returns — **Fix now**
- Where: `tests/Rochambeau.IntegrationTests/Identity/ChangeRoleTests.cs:18-31`, `tests/Rochambeau.IntegrationTests/Identity/HubSessionRevalidationTests.cs:35-51`. AC: AC-13, AC-08 (`test-plan.md:59,77`).
- Problem: AC-13's "Administrator in the acting identity" is asserted only through `/me`. `/me` reads the role from the database (`GetOwnProfile.cs:20-27`), not from `ICurrentAccount`. The hub `WhoAmI` test uses only a Player. The claim-to-role mapping is covered only by the unit test `AccountClaimsTests.cs:16-30`.
- Resolution: follow-up TDD task. Add an Administrator case to the hub `WhoAmI` test: promote the Account, log in again, connect, and assert that `ICurrentAccount` returns the username and `AccountRole.Administrator`.

### R7 — [stage-1] The AC-14 unit row names a Domain rule that does not exist — **Fixed in review (test-plan)**
- Where: `docs/features/accounts/test-plan.md:84` vs `src/Rochambeau.Api/Modules/Identity/Application/Register/RegisterAccount.cs:61`, `Infrastructure/Persistence/Account.cs:11`. AC: AC-14.
- Problem: the row asks for a unit test of "the Domain creation rule". In fact the Register handler sets the Player role, and the entity has it as a default. No unit test exists. The behaviour itself is proven by `RegisterTests.cs:140`.
- Resolution: the row is re-worded to the integration level and points at `RegisterTests.AC14_a_role_in_the_body_is_ignored_and_the_account_is_a_player`. No code change.

### R8 — [stage-2] The JSON-body check misses a body with no `Content-Length` on HTTP/2 or HTTP/3 — **Fix now**
- Where: `src/Rochambeau.Api/Common/Http/JsonBodyMiddleware.cs:34-35`. AC: n/a (`contracts/openapi.yaml` errorCode contract, R4).
- Problem: `HasBody` tests only `ContentLength > 0` or `Transfer-Encoding`, and HTTP/2 and HTTP/3 have no Transfer-Encoding. A streamed non-JSON body gets through and returns a 415, or a 401 for a Visitor, with no `errorCode`. The SPA is not affected.
- Resolution: follow-up TDD task. Use `IHttpRequestBodyDetectionFeature.CanHaveBody` and keep the length check as a fallback, with a unit test that has a body-detection feature but no `Content-Length`.
