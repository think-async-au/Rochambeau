### R9 — [stage-2] The JSON-body check has two edge cases around an empty body — **Fix now**
- Where: `src/Rochambeau.Api/Common/Http/JsonBodyMiddleware.cs:24-26,40-46`. AC: n/a (`contracts/openapi.yaml` errorCode contract; `DELETE /api/v1/session` has no `requestBody`).
- Problem:
  (a) Since T36, on HTTP/2 Kestrel derives `CanHaveBody` from END_STREAM, not from the declared length. A bodyless request that sends `content-length: 0` on HEADERS and END_STREAM on a separate empty DATA frame (some proxies and hand-written clients) has `CanHaveBody == true`, so a log-out `DELETE` with no Content-Type now gets `400 common.invalid_request`. The reviewer's Kestrel probe shows `HTTP/2 DELETE canHaveBody=True cl=0`.
  (b) This predates T36. A request with a non-JSON Content-Type and an empty body (`text/plain`, `Content-Length: 0`) has `CanHaveBody == false` and passes the check. Routing then picks the framework's 415 endpoint, and a Visitor gets `401 identity.not_authenticated` (not documented for registerAccount) while a logged-in caller gets a 415 with no `errorCode`.
  The SPA, HttpClient and TestServer trigger neither case.
- Resolution: follow-up TDD task. Under `/api`, treat an explicit `Content-Length: 0` as no body, and reject a request that has a body **or** carries a Content-Type when that Content-Type is not JSON. Add unit cases for `DELETE`, no Content-Type, `contentLength: 0`, `canHaveBody: true` (expects `next`) and for an empty-body `text/plain` (expects 400), plus an empty-body `text/plain` case in `BadRequestBodyTests.cs:38-56`.
